# 高倍速自适应生成

## 使用入口

世界设置 → 模拟器 → **AI 生成性能 · 高级诊断**。默认开启“自动优化高倍速生成”，关闭后新请求逐项执行，已有计划和历史保持不变。此开关不调整活跃度、事件概率或对白预算。

低于300×保持独立请求；300～999×每批最多4个子任务，1000～2999×最多8个，3000×以上最多12个。实际数量还受输入预算、输出预算、近期耗时、失败率和任务兼容性限制。并发上限仍为2，内存中的请求等待者上限32，不会随速度无限增长。

世界时间快于模型吞吐时，内容仍可能落后。面板显示待处理数量、平均批量、请求耗时、平均/P95等待、近期队列峰值、虚拟内容落后时间、今日所有世界合计请求与Token。最近100批的“完整返回率”仅表示结构完整，逐项校验仍可能拒绝某项内容。费用只在用户提供两项模型单价时估算。

## 实现与一致性

- 本地调度先生成带稳定ID、参与者、发生时间、消息/对白/阶段配额的计划。关闭/开启优化使用同一计划器，不为批处理再次抽样。调度使用计划消息头，避免模型响应速度和措辞改变后续计划。
- 新线上任务采用1～3条的固定配额，受全局与角色条数配置约束。新普通场景采用短活动1阶段、其他活动3阶段，沿用事件重要性对应的对白总预算。优化开关两侧均遵循该契约。旧队列继续原有生成协议；旧版自由输出本来没有固定条数，不能宣称与旧版任意模型实际输出逐条等量。
- 同一会话的下一次生成依赖前一次写入完成。大型事件单独处理，并阻止继续展开依赖其事实的后续规划。正在阅读的会话优先，但不会越过依赖。
- 线上任务仅在同世界、同发送者、同参与者以及授权人物/关系/记忆/历史/背景认知完全相同时合批。不同私聊的私人资料不会放进同一模型上下文。同世界本身不足以判定可合批。
- 一个线下主事件的阶段可以合批，分别保留阶段ID、时间范围、人物和对白数。不同主事件不共享私有场景上下文。客观生活描述可在同世界中共享世界基础设定，禁止添加对白或改变主事件事实。
- 重复的输入字段只传一次；响应采用`batchId/results/taskId`映射。未知ID忽略、重复ID拒收，合法发送者、时间范围、长度、Markdown、引用、@、表情和GIF仍由原校验器校验。
- 每项单独保存。消息不足先暂存，完整配额才形成独立气泡并完成任务；不会以摘要补足。场景缺早期阶段时暂存合法后续阶段，仅发布连续完成的阶段。截断批次仅抢救已闭合、可解析的子结果，不猜测缺失JSON。
- 失败只重试缺失或非法项，并缩小后续批量。网络、429、超时保留任务，自动尝试有上限，可手动重试；解除应用内部预算限制后可继续预算挂起任务。服务商额度错误仍须解决服务商额度。

## 持久化与积压控制

数据库升级到v13，新增队列复合索引和性能日志时间索引，保留旧历史。每个世界/提示词版本共用一份不可变快照，轻量任务只保存引用；完整备份同时导出快照与阶段草稿。快照缺失会明确挂起，不能偷偷换用当前提示词。

每次只加载最多48个可候选任务，不会把全部历史队列放进内存。积压达到256项后停止细粒度展开，保留未展开虚拟区间与检查点，恢复吞吐后续算；一次已开始的规划段可略超过阈值。HUD时间仍可前进，内容不会因追赶而丢弃。已完成历史不会被清理来降低积压。

暂停或时间控制版本改变时，不允许在途结果推进世界。浏览器重启后在独占锁内回收遗留running声明。已提交结果使用稳定ID防重复，未提交结果按原快照恢复。无浏览器锁的测试环境使用原有本地互斥。

## 可复现验证与收益边界

运行：

```sh
npm test
CHROMIUM_PATH=/path/to/chromium npm run test:e2e -- tests/e2e/adaptive-batching.spec.ts
npm run build
```

可选输出基准原始统计：

```sh
AQUARIUM_BENCHMARK_FILE=/tmp/aquarium-benchmark.jsonl npm test -- tests/adaptive-batching.test.ts
```

测试覆盖固定种子42、相同24小时、5/20/50人、1/100/300/1000/3000×、开关两侧计划一致性；实际排空验证消息、对白和阶段配额。另测多团体/长场景、截断、非法子项、网络/429/超时、暂停、备份恢复、速率切换、预算恢复、隐私隔离和背压。桌面1440px与手机390px验证真实浏览器IndexedDB、批次写回、开关持久化、刷新后暂停及页面宽度。

**使用确定性本地Provider，未调用用户付费API。** 请求数是真实执行适配器调用次数，Token由测试Provider按JSON字符数估算；延迟、吞吐和堆内存是本机测试环境数据，不代表在线模型服务性能。堆增量受GC影响，不是精确峰值。规划矩阵与实际排空范围详见基准结果，不把规划验证冒充真实API吞吐。

基准原始记录见 [ADAPTIVE-BATCHING-BENCHMARK.json](ADAPTIVE-BATCHING-BENCHMARK.json)。规划包含30组开关/速度/人数组合；自然日常的实际排空覆盖5/20/50人、1000×，多阶段场景的实际排空覆盖20人、300/1000/3000×。

普通私聊主要受因果依赖和私人认知隔离限制，因此没有达到300×减少40%、1000×减少60%的整体目标；长场景样本达到了40%，尚未达到60%。不通过跨私聊混入秘密、删除气泡或减少阶段来追求目标。JSON封装会增加输出Token；主要节省来自共享输入及网络往返，而完整内容的输出成本仍然存在。若模型输出速度不足以追上高倍率，系统保留积压，不能承诺完全消除滞后。

这些时间包含本机数据库操作和测试替身调用，不包含真实网络与模型推理。积压峰值相同反映计划数量相同，不能把它解释为实时积压已经降低。队列容量另有256项背压测试；故障重试通过独立用例验证，不混入无故障吞吐统计。

最终回归还覆盖“回到过去”对待办依赖及消息引用的映射、部分消息中的GIF气泡位置、回收站恢复后续跑。完整浏览器回归中的移动观察管理用例在并行压力下出现一次超时，独立重跑通过；100人选择性观察的60秒性能用例同样在并行压力下超时，独立重跑35秒通过（全量24项/选择性6项）。这里保留测试运行限制，不将本机资源竞争计作模型吞吐收益。

本轮验证共覆盖252个单元/集成用例及52个浏览器用例（包含上述独立重跑），生产构建通过。测试预算未消耗用户API额度。
