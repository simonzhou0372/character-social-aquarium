# 架构与数据模型

## 边界

- `src/pages` / `src/components`：React 展示、表单与交互；使用 Dexie liveQuery 订阅本地数据。
- `src/core/types.ts`：统一实体定义与 Zod 运行时格式校验，统一字符串 ID。
- `src/data/db.ts`：Dexie 分表、索引、迁移、Web Locks 入口。
- `src/core/simulation.ts`：可脱离 UI 测试的纯生活规划、种子随机数与社交权重。
- `src/core/planner.worker.ts`：浏览器生活规划线程；Node 测试使用相同纯函数。
- `src/core/engine.ts`：时间恢复、调度、预算、快照、原子提交与幂等。
- `src/ai/provider.ts`：兼容 Provider、连接/超时/取消/错误分类、测试 Mock。
- `src/ai/orchestrator.ts`：上下文、知识检索、消息校验、用量记账、资料与记忆任务。
- `src/ai/prompts.ts`：七类默认规范、版本配置、任务路由、生成规则。
- `src/data/backup.ts`：版本化备份与引用完整性校验。

选用 React state + Dexie 订阅替代额外 Zustand：数据库承担持久状态，界面只保存表单/导航等短期状态。这样避免维护第二份容易与 IndexedDB 不一致的全局实体副本。

## 表与关系

| 表                    | 内容及关键索引                                                   |
| --------------------- | ---------------------------------------------------------------- |
| characters            | 全局角色；id、name                                               |
| worlds                | 世界事实、场景、时区                                             |
| memberships           | 多对多世界成员；worldId、characterId、复合索引                   |
| groups / groupMembers | 多世界团体与世界内成员；groupId/worldId/characterId              |
| relationships         | 有向边；worldId/from/to 复合索引；锁定边界                       |
| conversations         | 世界、参与者数组索引、团体、控制角色、lastAt                     |
| messages              | 会话、seq、simAt、realAt、eventId、source；会话+序号复合索引     |
| cursors               | 会话+阅读者，观察者和角色的 ID 命名空间独立                      |
| events                | 世界、时间、参与者、多成员共同活动、地点、phone                  |
| states                | 世界+角色当前活动，引用实际 eventId                              |
| memories              | 世界、owners 多值索引、时间、会话索引；knowledge/episode/summary |
| checkpoints           | 每世界模拟/现实时间、随机种子、暂停、速度、补全目标及请求数      |
| settings / profiles   | 简单选项、预算、用户身份；API 配置独立于备份                     |
| usage                 | 按 UTC 日期记录请求、Token、消息；不伪造价格                     |
| promptConfigs         | 独立全局提示词配置、版本、七个条目与生成规则                     |
| taskSnapshots         | 当前补全批次持久化提示词快照                                     |
| taskLogs              | 任务类型、世界、提示词版本、状态，无密钥和完整请求正文           |

数据库 v1 建立基础表；v2 添加提示词与任务日志；v3 添加补全快照；v4 添加记忆会话索引。迁移只增加结构，不清空历史。备份格式 version=1，提示词字段可选，以兼容早期基础备份。

消息、事件、角色、图谱使用同一组实体 ID。人物身份差异在 membership 覆盖中表达。用户以 `user` 作为消息发送者，昵称/简介从设置读取。当前版本有一个用户身份、一个观察者阅读身份。

`realAt`、检查点 `realTime` 与 API 用量日期使用现实 UTC 时间。事件、消息、记忆与场景共用数值模拟时标；旧档兼容保留原 epoch 毫秒值，新世界通过 `calendarAnchor {tick,date}` 映射到独立的世界日期。世界日期用整数日序与日内分钟运算，支持 1～999999 年，避免将六位数年份转换成不安全的巨型毫秒时间戳。时区仅用于默认日期及旧档迁移。展示、AI 当地日期和作息读取统一的 WorldCalendar。

## 生活与社交决策

每个事件使用 `[start,end)` 半开时间区间。确定性作息先判断跨午夜睡眠，再判断饭点和学习/工作，其他时间休息。规划按小时边界切开，多日恢复一次可以规划多小时，但不会把整天误判为同一状态。

随机数采用保存的 LCG 状态，重跑同一检查点产生相同基础规划。共同活动先选空闲成员及存在的关系边，再用一条多参与者事件替换两条单人事件，避免同一时间占据互斥地点。

社交权重结合手机可用程度、手机习惯、主动/回复倾向、亲近、最近行动的冷却、对话陈旧程度、心情与随机项。睡眠和被用户控制的角色权重为零。最近发送者不会机械地立即接自己的话。每段最多选一个发言角色，可输出 0～3 条；不会遍历每人都发 AI 请求。关系边可以产生新的稳定 ID 私聊。

阅读与回复是不同判定：手机可用还要通过手机习惯/随机检查才能更新角色游标；是否回复再由权重选择。观察者游标只在当前聊天底部且页面可见时更新。

## 恢复、事务与标签页

计算目标模拟时间 = 保存的模拟时间 + 实际时间差 + 在线可见时间差 × (速度 − 1)。已暂停世界不累积离线时间。目标时间在恢复任务开始时固定保存；长恢复开始前保存提示词快照。

分段精度：一天以内最多按小时，一周内最多三小时，一个月内六小时，更长按天规划；内部日程仍按小时边界。AI 请求受每批补全预算与每日预算限制，超过补全预算后可继续安排本地生活但不补生成额外对白。

规划在 Worker；网络请求在数据库事务外。随后一笔事务检查原检查点时间/种子未变化，并写入活动、状态、游标、消息、记忆、用量与新检查点。事件和模拟消息 ID 含世界/原时间/角色等稳定部分。检查失败则丢弃候选提交。

支持 Web Locks 的浏览器在整个规划/生成/提交期间持有世界锁，防止多个标签页重复付费与执行。标签页关闭自动释放锁。缺少该 API 时，事务比较检查仍防止重复提交，但不能保证候选 API 请求不重复。暂停立即取消本标签页任务并增加控制版本，事务拒绝其他标签页的旧任务提交。保留已提交段，放弃未提交的未来目标及快照；继续时从已保存模拟时间建立新的现实锚点，不补算暂停期间。

## 记忆与安全

关键词检索用中日韩相邻双字片段，结合重要程度与近期性排序，最多取六条。先按世界、知情角色、事件发生时间过滤，再评分；不会把所有作品材料塞进请求。事件记忆只授予实际参与者；会话摘要保留会话知情范围。

AI 无权直接修改图谱或日程。生活描述只能返回一个短描述，代码保留原事件 ID、类型、时间、地点、成员。对白严格限定指定发送者、字符串数组、条数、字符数、时间偏移及常见禁止格式。不合法输出整批不提交，不对正文按换行猜测拆分。

备份导入先 Zod 校验，再检查引用、重复 ID、消息序号、事件结束时间等，最后事务完整替换。没有隐式级联删除：对正在使用的成员关系，UI 不提供危险删除；群成员有历史消息时不能直接移除。

## 扩展位置

新 Provider 实现 `Provider.complete` 即可；多模态可从 Completion/Message schema 版本化扩展；新活动决策扩展纯规划函数；新知识检索实现替换 retrieveMemories。当前没有空插件执行器、同步后台、向量库或预留服务进程。

## 创建向导、前台加速与上下文预算增量

数据库 v5 为现有检查点补充默认上帝模式，保留原有 speed。新增世界默认 god / 30×。`core/time.ts` 计算：目标模拟时间 = 当前模拟时间 + 总实际时间差 + 明确可见在线区间 × (倍率 − 1)。初次加载、后台、断网不提供加速区间；不会将关闭期间的时间乘以倍率。真实模式始终 1×；两种模式暂停均冻结世界。数据库 v6 增加历法锚点、背景实体兼容字段、线下场景与认知表，保留所有旧消息及事件。

长前台批次也持久化固定目标、实际目标和提示词快照，并标记 foreground/offline，避免普通加速误用离线提示词。每段实际锚点按本批次实际有效速率推进，不再无条件除以保存的 speed。回退创建独立世界分支，并重映射会话/事件/消息引用。

新私聊 ID 使用世界和排序后人物 ID 的 SHA-256，避免 UUID 组合不断增长。阅读游标兼容此前已生成的较长组合编号，备份不因此失效。

`data/worlds.ts` 事务化创建世界、角色、团体及会话；世界包有独立格式和引用校验。世界外成员必须经过确认。`ai/drafts.ts` 为世界和团体分别生成经过校验的草稿，只有显式采用并保存才写实体。

`ai/context.ts` 在所有预算化 AI 任务前执行本地抽取压缩。世界事实、系统规范、最新用户消息、锁定边界是保护层；较早聊天和记忆按档位取舍，不发送头像。紧缩档用于有限恢复。任务日志保存压缩统计、完成原因及实际用量，不保存请求正文或密钥。输出因 length 截断也先记录真实用量，再决定是否进行一次恢复请求。

## 第二轮数据与调度

`core/calendar.ts` 提供 WorldDateTime 校验、闰年、整数日序、加减分钟、时标映射与格式化。`World.calendarAnchor` 使六位年份可安全落在较小的逻辑时标附近；初始日期与现实运行锚点分别保存。到达 999999 年末时自动暂停。`controlVersion` 阻止跨标签页暂停/变速前启动的响应在之后写回。

`scenes` 以 worldId/eventId/start/participants 建索引，保存完整场景和阶段；引用唯一主生活事件。`backgroundKnowledge` 记录 entityId、characterId、认知程度与带性质/来源的信息。背景实体复用原角色/团体 ID，并在规划和对白候选阶段排除。`data/knowledge.ts` 只传播实际在场听到或已读且明确说出的信息，不把私有记忆全量共享。

`core/activity.ts` 集中在线机会、冷却、话题节奏、群聊权重、接续及自然结束参数。以模拟时间分配 1/3/6/8/10 个每小时机会槽；沸腾和狂欢还会在同一调度段内按独立概率开启 2–3 个互不冲突的会话。所有档位仍受作息、关系、手机、用户控制和个人主动间隔影响。生活共同活动概率按模拟时长折算，独立于在线档位；线下抽样和每日数量另设。每六模拟小时最多请求一次代表性生活描述，避免每次聊天都调用额外描述任务。Provider 请求并发上限为 2。

`core/scenes.ts` 是生成与备份共用的纯校验器；`ai/scenes.ts` 生成结构化阶段，使用任务快照、各角色私有记忆、关系与知情记录。场景和主事件及参与者事件记忆在同一事务提交。线下内容失败独立记录，不回滚同段已验证的线上内容。原始场景不会被记忆整理删除。

旧六类提示词配置自动补入第七类，保留已有自定义内容；完整备份仍兼容 format/version 1，新增集合默认空数组。v6 升级不清理旧消息、关系、事件、头像、密钥或预算数值。

## 第四轮运行链

浏览器统一使用 `runWorld({deferContent:true})`：模拟时钟锚点独立于事件检查点；本地规划和主事件事实先原子提交，AI 内容任务同时写入 IndexedDB，再由 `drainContent` 处理。内容队列使用独立的世界锁，不占用生活调度锁；Web Locks、事务领取与有期限的运行状态共同防止重复执行，异常终止可恢复。测试和诊断脚本保留同步 Provider 注入路径，以复用既有模拟验收。

`ContentJob` 保存任务类型、主事件、原时间、提示词快照和重试状态。AI 只能补充既定活动描述／对白，不能改变活动时空。提交前核对暂停及控制版本。迟到的消息使用原虚拟时间并标记补全，序号只作为到达及阅读游标，不重新编号；展示顺序按虚拟时间、序号排序。

线下场景先保存 `plannedPhases`，每阶段持久化后递增 `generationCheckpoint`；对话建议数量不再作为整场拒收条件，身份、时间和文本格式继续硬校验。续写保持主事件唯一，不重写已成功阶段。

GIF 二进制在 `resources` 中使用 Blob 与 SHA-256 去重，`gifAssets` 保存作用域和元数据；消息引用资源目录 ID。读权限按当前世界、当前会话团体和发言角色计算，模型只收到有权使用的 ID 与描述。资源目录软移除不删除历史使用的二进制。

大型事件由 `majorSchedules` 的虚拟时间截止期保证发生，使用稳定周期序号；`majorEvents.eventId` 引用同一主生活事件，通知只引用该大型事件。AI 细节生成与事实调度分离，失败不会回退时钟或制造第二个事实。关系后果受开关、参与者、幅度与锁定检查约束，已执行结果不会重复加成。

新增数据库版本为 v7、v8、v9，完整迁移与回归证据见 [第四轮验收记录](ROUND-FOUR-VALIDATION-2026-10-23.md)。

## 观察、演化和报告数据链

v10 添加 observationConfigs、observationCoverage、backfillJobs、evolutionRecords、evolutionCursors、worldReports、reportCursors，以及事件结束时间和场景开始时间的世界复合索引。备份集合默认空数组，旧世界不自动静默、不启用演化或报告。世界包包含观察配置并在导入时映射 ID。

`selective-observation.ts` 计算角色、团体与 CP 的范围并集，但分别约束允许的会话与事件，不递归扩展关系。引擎按活跃 ID 索引读取资料、状态与会话；静默元数据仅用于范围解析和低频宏观抽样。范围修改递增控制版本，取消旧任务，将无关内容任务挂起。`dormant-influence.ts` 只生成与观察者直接有关的有限宏观影响，不改变观察配置。

`backfill.ts` 在世界锁下按虚拟日提交代表性主事件、记忆及内容任务，再由已有 AI 队列生成对白和场景。范围截止使用已提交模拟时间；历史占用、稳定 ID、覆盖区间和提示词快照确保可恢复。维护调度等待当前世界短批次释放锁，避免回溯被持续抢占。AI 未完成与时间区间已检查是分开的状态。

演化结果写入世界 Membership 的 evolved 覆盖层，锁定策略由世界开关与角色 evolutionFields 共同决定。证据必须来自已发生的参与事件；核心身份没有可写路径。记录保存前后值、原因和依赖链，撤销检测后续依赖与手动冲突。历史请求依据演化链及知识的 knownAt／learnedAt 过滤未来状态。

报告周期由整数历法计算，游标分批登记归档，稳定周期 ID 去重；本地事实整理与可选 AI 结构优化分离。AI 仅能选择已给定的来源 ID，正文渲染原事实。长周期复用下级来源，同时保留重要原始事件。报告使用独立提示词，不继承角色聊天排版限制，也不进入角色共享记忆。
