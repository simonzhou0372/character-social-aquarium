# 第六轮：费用审计、生死与团体历史

## 先看费用结论

本轮读取了本地原始 `LastSevenDays_Archive` 与传输用量日志，未修改实验档案，也未把档案导入用户存档。100 人、24 团体、7 个虚拟日的原始实验记录为：

| 指标               |         已保存的实测记录 |
| ------------------ | -----------------------: |
| 成功请求           |                    2,532 |
| 失败传输记录       |                        1 |
| 输入 Token         |                6,548,214 |
| 输出 Token         |                  373,600 |
| 输入占已记录 Token |                    94.6% |
| 线上消息           |                    3,538 |
| 线下对白 / 场景    |                   56 / 8 |
| 重大事件           |          9（含终局记录） |
| 用户反馈的总费用   | 约 ¥15，未取得可核验账单 |

原传输脚本明确使用 `thinking: {type: "disabled"}`，所以不能把这次消耗解释为“开启高思考”。输入上下文占比高是已证实的线索，缓存命中情况则没有留下证据。原代理使用 Anthropic Messages 上游并丢失缓存类别，不能事后将所有输入标成缓存未命中。应用汇总表又带有估算值，与传输日志存在差异；没有用新账本伪造或覆盖旧记录。

2,532 次成功请求与 2,348 个最终内容任务的差值，不能直接认定为重试：场景阶段、修复和维护请求没有逐次关联信息。原系统的日程、看手机、社交决策已经在本地执行；记忆整理本来就是手动且幂等，演化已有事件门槛和七天间隔，不能把这些现有机制算成本轮节省。

数字明细见 [审计 JSON](ROUND-SIX-COST-AUDIT.json)，通过 `node scripts/audit-ai-cost.mjs` 在有本地原档案的环境重新生成。脚本仅输出数值汇总，不输出密钥或聊天正文。

## 已实施的优化与证据边界

- 任务级推理策略：自动模式下，普通任务关闭已知 DeepSeek 模型的思考；复杂事件和演化采用低强度，小说采用高强度。可以改为遵从用户或高级路由。默认复用同一个模型、同一个接口和密钥，不要求另购模型。明确的旧版 on/off 设置继续生效。
- 只向已知支持的模型发送专用参数。第三方代理需显式勾选兼容；参数被拒绝时最多回退一次，原请求和回退各有账本记录，并记住该模型不支持该参数。
- 稳定世界/角色前缀及集合顺序，动态状态和协议后移；不重排聊天时间顺序，不合并不同知情范围的私密上下文。缓存属于服务商的尽力行为，不能保证命中率。
- 线上单任务可使用短字段 JSON，程序补全固定发送者，再走原有长度、发送者、时间、@、引用和表情校验。不删除消息、不按换行拆泡，不改变已计划的条数；批量生成继续使用原任务协议。
- 保留既有自适应批处理，按知识权限和参与者分组，保留全部计划及恢复检查点。拒绝为省钱把所有角色的私人知识混成一个请求。
- “普通生活描述沿用本地事实”是显式可选项，不改变已保存事实。原实验有 28 个此类任务，最多对应约 1.1% 的原请求，不能靠它宣称费用减少三成。
- 节约模式需主动选择。观察对象不会被静默修改，线下生成预算仍独立于线上活跃度。

对真实档案的 **2,304 个已保存聊天任务** 做无付费协议回放，所有 3,538 条消息的正文、发送者、会话、时间保持一致。重建的通信对象从 **537,732 字节变为 392,580 字节，减少 27.0%**。这是重建对象字节数，不是服务商 Token 或账单；原完整 wire 请求、可选响应字段未保留。Token 数仅使用本地估算器。详情见 [回放 JSON](ROUND-SIX-ARCHIVE-REPLAY.json)。

## 用量分析与人民币预算

入口：**设置 → 用量分析**。按世界、模型、任务筛选，查看缓存命中、推理、输入输出、趋势、每百条线上消息及每千条线下对白的已知费用、重试和验证状态，并可导出 JSON。旧汇总记录保留，新账本从升级后的请求开始采集，不补造历史。

账本仅存实体 ID、任务元数据、数值及计费配置快照，不存完整提示词、密钥或思维链。推理 Token 已包含在服务商输出 Token 时不重复计费。失败但已返回用量的响应同样入账；返回了结果却没有用量时，费用显示未知，并保留预算预留，避免把未知费用当零。

定价需用户确认，标注来源和日期；内置参考来自 [DeepSeek 官方价格页](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，快照日期 **2026-10-28**，并非永远有效。峰谷时段由用户明确选择；默认高峰保守估算，不自动判断中国节假日。USD 价格未配置汇率时不冒充人民币。即使字段齐全，显示值也是按已配置单价估算，不是账单。

人民币预算支持现实日（UTC）、虚拟日、最近七个虚拟日、不限制。虚拟预算以对应世界当前 HUD 日期记支出，同时保留内容实际发生日期，用于离线/历史任务的来源分析。并发请求原子预留，超预算保留任务，额度增加、取消限制或日期更新后可继续；高倍率仅推进时钟，不会绕过费用门槛。“不限制用量”保留并发、重试和服务商限流保护。旧版 Token/请求限额仍独立生效。

如需要本机代理，可选运行 `node scripts/deepseek-proxy.mjs`，前端接口填 `http://127.0.0.1:8788/v1`。密钥由环境变量 `DEEPSEEK_API_KEY` 或本地 `.env.local` 提供；代理只转发，不实现第二套业务调度，不裁剪 `usage`，固定官方上游、限制并发和超时。不启动代理也能直接使用原兼容接口。

## 生死和组织状态

小说世界设置增加死亡风险、复活规则、亡灵交流和组织变化许可。旧存档默认禁止自动死亡，角色默认受保护；跨世界状态独立，不把旧版 inactive 猜成死亡。

- Alive / Missing / Dead / Resurrecting / Resurrected；死亡、失踪和复活中不进入普通生活、聊天、场景候选池。保留角色 ID、历史和关系。
- 自动死亡只能来自已发生的危险重大事件，角色需明确取消保护，满足世界规则、事件候选和实际在场约束；锁定的存活目标进一步阻止自动死亡。候选并不保证死亡。
- 复活需引用明确世界规则和事实条件；有条件复活的完成必须由用户确认。死亡不能直接改成普通存活以绕过复活链。
- 肉体、意识、能否交流分别记录。亡灵只在世界明确允许且事件显式指定时参与特殊重大事件，不能恢复普通线上聊天。
- 团体可紧张、决裂、解散、和解、重组；成员退出/重返、新团体继承链分别留痕。不能从解散直接跳成重聚，不复用新团体为旧团体抹掉历史。

入口：**世界与团体 → 人物生死与团体历史**。用户确认需先暂停世界，选择已发生的重大事件、引用事件原文、填写原因，预览后再次确认。每条变化可追溯到原事件与角色。手工确认仍受世界死亡/复活规则和状态转换检查，不是任意篡改开关。

状态变化写入统一事件后果、当事人/在场者记忆、通知、时间轴及报告来源。死亡/退群期间的群聊不会作为复活/重返后的天然知识；旁人主动引用并告知的内容另按可见消息处理。世界回溯从截止前事件恢复生命和组织状态，重新映射事件 ID，避免未来复活污染过去。

## 存档与验证

数据库升级到 v15，新增请求账本、叙事变化和组织状态表；可选字段不重置旧角色/世界/时间。完整备份包含新表；只导入世界设定时不携带依赖历史事件的死亡状态。回收站永久清理会同时维护这些引用。

测试覆盖价格分类/零值/未知字段/失败计费、原子预算、推理兼容回退、压缩协议、旧存档导入、人物保护/失踪/复活、跨世界隔离、亡灵与普通调度隔离、团体继承/退出/重返、历史知情边界及世界回溯。浏览器在 1440px 和 390px 验证价格确认、预算刷新持久化、事件确认和死亡历史展示。浏览器请求由本地拦截响应驱动，不接触真实密钥或用户存档。

### 本轮实际执行结果

- `npm test -- --maxWorkers=2`：20 个测试文件、280 项全部通过。最后的阶段用量归属和回溯修正另有针对性回归通过。
- Playwright 全套：59 项通过；最后修改后追加桌面/手机的用量、生死、队列用例 6 项通过。
- `npm run build`：通过，仍有现有主包超过 500 kB 的体积提示。
- 生产离线检查：Service Worker 缓存、离线刷新、自定义提示词持久化通过，页面无脚本错误。
- 回溯专项：27 项通过，覆盖成员后来归队但旧分支仍应离团，以及过去分支不应出现未来派生团体。
- 阶段恢复专项：部分场景跨备份恢复后，先前请求生成的对白仍归属先前账本记录，只在真正发布阶段后计入有效内容，重试不重复计数。

固定种子 24 小时的本地 Provider 压测，在保留消息/阶段的前提下，5/20/50 人三组分别从 80 次请求降至 74/75/75 次。该工作负载含四个明确可合并的顺序生活描述任务，保证测试不会依赖偶然存在的私人聊天合并机会。数字用于验证队列与协议，没有实测服务商费用；短字段、批次外壳和缓存单价的权衡仍须以新账本衡量。
